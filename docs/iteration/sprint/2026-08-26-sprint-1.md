# Sprint 1（2026-08-26）—— 前端布局与 parse_chunk_embed 交互优化

> 文档归属：`docs/iteration/sprint/`。本轮围绕「界面自适应 + 函数子画布可读性 + parse_chunk_embed 提速与交互」展开。
> 增量项目文档（非 sprint 记录）统一放在 `../`（即 `docs/iteration/` 下一级）。

## Sprint Goal

在**不改变现有问答功能语义**的前提下，提升 GUI 的可操作性与反馈：

1. 支持用户手动拖拽分栏缩放，其它面板自适应调整。
2. Function Subcanvas（函数子画布）提供**全屏**查看，并在非全屏下把调用线画得更整齐。
3. parse_chunk_embed（最耗时环节）交互优化：图片可放大、支持「载入最近一次 Embedding」与「重新生成」，并定位慢因、提出预分割加速的探索方向。

## Backlog（用户故事 + 验收标准）

| ID | 用户故事 | 验收标准 |

## 任务拆解

- T1 布局：`App.jsx` 分隔条 + `splitPct` 状态 + CSS 拖拽样式。
- T2 全屏/连线：`App.jsx` `fnFullscreen` 状态 + 全屏按钮 + `defaultEdgeOptions=smoothstep` + 进入全屏后 fitView。
- T3 图片放大：`FunctionTraceNode.jsx` 媒体图点击 → lightbox。
- T4 载入 Embedding：后端 `parse_chunk_embed` 支持 `load`/`regen` 模式 + `~/.pqa/embed_cache/` 缓存；`FlowNode.jsx`/`App.jsx` 加按钮。
- T5 提速分析：复现/看日志，输出慢因与预分割方向到 `docs/iteration/embed-optimization.MD`。

### 权衡与理由

- 拖拽分栏用**自定义分隔条**而非引库：依赖少、可控；占比存于 `splitPct`（未持久化，刷新回默认 55/45，可后续加 localStorage）。
- 「载入 Embedding」跨会话命中缓存时 `session.docs` 不在内存，`evidence/answer` 会提示先 run——已在 `load` 分支保留该限制并建议"重新生成"重建 docs。
- 提速方向（预分割）只做分析不落地，避免在未充分验证收益前引入解析复杂度。
