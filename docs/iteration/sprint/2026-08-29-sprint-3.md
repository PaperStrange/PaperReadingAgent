# Sprint 3（2026-08-29）—— 数据源抽象 B：本地目录/URL/manifest/论文ID 多源 + 前端切换 UI

> 归属：`docs/iteration/sprint/`。输入：`../refactor-analysis.MD` 主题 B（前端2：load_index 数据源写死本地绝对路径）。
> 范围：windows 分支迭代；完成后同步 main 的 windows 部分并对两分支做 code review；MAC 验证跳过。
> 原则延续 Sprint-2：**默认本地目录行为不变**（回归为证），新增能力只做加法。

## 1. Sprint Planning

- **Goal**：在行为不变的底座上，把"数据源"从单一 `paper_directory` 假设解耦为 **local / remote(urls·arxiv·doi) 多源 + manifest 元数据增强**，前端 Config 节点提供切换 UI；本地目录默认路径完全保持现状。
- **勘察结论（paperqa v2026.1.6.dev10+g36348d0ca 能力边界）**：
  - `get_directory_index(settings, build)` 只读单一 `IndexSettings.paper_directory`；`manifest_file` 仅做元数据增强（`maybe_get_manifest`）。
  - `Docs.aadd_url(url)` 可下载全文解析；无内建"论文ID→全文"解析。
  - arXiv 可用公开 API（export.arxiv.org，免 key）解析 PDF 链接；DOI 可经 `clients.unpaywall`（免 key，仅需 email 参数）取 OA PDF。
  - 结论：**远程源统一"下载到 staging 目录 → 复用现有索引/解析管线"**（Strangler 风格，不另起检索分支）。
- **团队与产能**：1 人（AI 开发者），预估 **31 点 / ~24h**。
- **周期**：2026-08-29 起，Backlog 全 DONE 且回归证据齐备为止；**后续 Sprint 全部 hold，完成后先做 windows/main code review**。
