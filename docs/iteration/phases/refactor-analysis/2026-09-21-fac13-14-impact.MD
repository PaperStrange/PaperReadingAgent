## 1. F-AC13：节点运行按钮首次点击被吃掉

### 1.1 根因（代码证据）

`paper-qa-script/reactflow-paperqa-prototype/frontend/src/FlowNode.jsx`：

| 位置 | 内容 | 是否带 `nodrag nopan` |
|---|---|---|
| `:120` | `params` 文本区 | ✅ 有 |
| `:133` | `<div className="node-actions">`（Run Upstream / Run Node / Run From Here 三个按钮 :134/:137/:140） | ❌ **没有** |
| `:146` | `<div className="node-actions embed-actions">`（载入 Embedding :147 / 重新生成 :154） | ❌ **没有** |
| `:177` / `:242` / `:249` | `node-output` 块（含三个复制按钮） | ✅ 有 |

ReactFlow 在 pane 上用 d3-drag 处理 `mousedown`；位于可拖拽区域内的按钮若没有 `nodrag`/`nopan`，首次按下会被判定为"开始拖拽/框选"，`click` 事件因此不触发——**与用户描述"点 1~2 次无响应、第 3 次才 run"一致**（拖拽判定完成后，后续点击不再被当作拖拽起点）。

### 1.2 修复面（最小改动）

- 方案 A（推荐）：给两处 `.node-actions` 容器加 `nodrag nopan`（与同文件既有两处用法完全一致，改动 2 行）。
- 方案 B：逐个按钮加 class（5 行，粒度更细但重复）。
- 不改：CSS 无需改动；`run-btn` 样式不变。

### 1.3 影响面（谁会受影响）

| 受影响对象 | 影响 | 处置 |
|---|---|---|
| `verify/gui_check_s5.mjs:57`、`verify/gui_check_s7.mjs:27` | 它们用 `cards[idx].querySelectorAll(".run-btn")[1].click()`（**程序化点击**，绕过 mousedown）→ **不受修复影响，也不会因此变红** | 复跑确认 |
| `verify/gui_check_s4.mjs` / `gui_check_config_schema.mjs` | 不点运行按钮 | 复跑确认（smoke） |
| 拖拽手感 | 修复后**无法再从按钮行拖动节点**（这正是目的） | 需你确认可接受 |
| 其它节点类型（`FunctionTraceNode` 的按钮在子画布内的 toolbar，非节点体） | 不受影响 | — |

### 1.4 验收证据设计（关键：真实鼠标序列）

新增 `verify/gui_check_fac13_click.mjs`（gui 档）：
1. 定位某节点卡片的 `.node-actions` 按钮，取 `boundingBox()`；
2. 用 `page.mouse.move(cx, cy)` → `page.mouse.down()` → `page.mouse.up()`（**真实鼠标**，非 `.click()`）；
3. 断言 **第一次** 点击后该节点 `data-status` 进入 `running`（或 `run_id` 变化）；
4. 反向对照：对未修复代码跑同一检查应 FAIL（把这条写进检查注释，便于复现 bug）。

## 2. F-AC14：三个复制按钮共用"已复制"状态

### 2.1 根因（代码证据）

`FlowNode.jsx`：单一 `copied` state（`:42`）+ 单一 `copiedTimerRef`（`:43`）+ `flashCopied()`（`:50-54`）被三个按钮共用：

| 按钮 | 行 | 文案来源 |
|---|---|---|
| 复制 output | `:182-187` | `{copied ? "已复制 ✓" : "复制 output"}` |
| 复制报错 | `:194-199` | `{copied ? "已复制 ✓" : "复制报错"}` |
| 复制答案 | `:216-224` | `{copied ? "已复制 ✓" : "复制答案"}` |

点任意一个 → `setCopied(true)` → **三处同时变成"已复制 ✓"**（与用户观察完全一致）。

同仓库的正确写法（可直接照抄）：`FunctionTraceNode.jsx:27/:155` 的 `errCopied` 是**每按钮独立** state。

### 2.2 修复面

- 三个独立 state + 三个 timer ref（或一个 `useRef({})` 字典）；
- `flashCopied(kind)` 只置对应 kind；
- unmount 清理循环清三个 timer（现有 `:44-49` 的清理需同步扩展）。

## 4. 附：为什么这两个 bug 能存活 4 个 sprint

1. **既有 GUI 检查全部用程序化点击**（`.click()` 或 `evaluate(el => el.click())`）——它直接派发 `click` 事件，不经过 mousedown/拖拽判定，**结构上不可能触发 F-AC13**；`gui_check_s5/s7` 正是这样点运行按钮的。
2. **复制按钮的"文案状态"从未被断言**——`gui_check_s15_output_view` 只校验剪贴板内容，`error_copy` 只校验错误定位，没有人断言"点 A 不影响 B"。
3. 这正是用户 2026-09-20 反馈的"验收方式偏代码执行层、未覆盖人机交互面"的具体实例，已立卡 `TG-6`（验收指南须分栏标注"机器回归项 / 人工可感项"，并要求人工可感项给出真实操作步骤）。
