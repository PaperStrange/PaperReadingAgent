## CM-1 改写双闸模型（来源：3-LEARNED 1.67）

- **名称**：改写双闸模型（Transformation Two-Gate Model）
- **版本**：候选 v0（未入库；`MM-1` 交付后重裁）
- **模型描述**：任何"对既有产物做程序化改写"的动作，必须同时过两道闸才有资格执行——
  **①前置条件闸**（对**当前**输入断言"这一项确实需要被改"，过期清单/陈旧索引必须被挡住而不是照改）；
  **②可见等价闸**（等价性判据必须能**看见被改的那个面**：改注释就不能用 AST 证明注释完好）。
  两闸任一缺失即整项回退并点名。
- **使用时机**：批量折行、批量重命名、结构化迁移、自动修复脚本、任何"脚本改仓库文本/结构"的动作。
- **模型边界**：只管**改写**，不管"该不该改写"（那是设计决策）；对**新增**内容不适用（新增没有前置条件可断言）。
- **输入**：待改产物 + 改写脚本 + 该产物的"被改面"清单（注释/字符串/结构件/字节层）。
- **输出**：改写结果 + 两闸的机检证据（前置条件命中数、逐字拼回/结构等价的断言行）。
- **模型创始人**：本项目（源事故：2026-09-25 D4 自动折行脚本用**过期行号表**重跑，把注释切成
  `# 恒` / `# False，`，AST 检查看不见注释 ⇒ 无闸门可拦）。
- **来源**：`docs/3-LEARNED.MD` **1.67**；机制反例档案例 20；`1-WORKFLOW.MD` §6"自动化改写脚本的纪律"。
- **成功判据**：能直接生成一个可执行 workflow —— 至少含两步：`assert 前置条件`、
  `assert 看见被改面的等价`；缺任一步该 workflow 不成立。
- **状态**：候选（未入库）

## CM-2 证据归属模型（来源：3-LEARNED 1.68）

- **名称**：证据归属模型（Evidence Provenance Model）
- **版本**：候选 v0
- **模型描述**：一条结论的可信度**不高于其输入的归属强度**。"用标识符取结论"时，
  标识符必须**显式传入**，或**连同来源（仓库/分支/事件/版本）一起打印**供逐字比对；
  **格式合法不构成归属证明**——"看起来对"的输入比明显错的输入更危险，因为它不会被任何一步拦住。
- **使用时机**：查 CI 结论、查账本 run、引用提交 sha、引用卡号、引文溯源、
  以及**一切"我从某文档读到 X，于是按 X 决策"的场合**（本条的一般化，见 §"提取说明"）。
- **模型边界**：判"输入是否属于被验证的那件事"，**不判**"结论本身对不对"；对**明确亲手产生**的输入
  （当场命令输出）不适用（归属自明）。
- **输入**：标识符（sha / run id / 卡号 / 文档路径:行）+ 期望对象。
- **输出**：归属证据行（`head_sha=… branch=… event=…` / `path:line` / 原文片段）+ 逐字比对结论。
- **模型创始人**：本项目（源事故：2026-09-25 D5 轮询脚本的 `git rev-parse HEAD` 取自**另一个 cwd
  的仓库** ⇒ 拿别人的 CI run 当自己的证据，报 success 而我的提交还在跑；格式检查完全通过）。
- **来源**：`docs/3-LEARNED.MD` **1.68**；机制反例档案例 21；`1-WORKFLOW.MD` §6 第 1 条及其对偶"不猜标识符"。
- **成功判据**：能生成一个 workflow：每个被引用的标识符，要么由本次执行**当场产生**，
  要么附**来源打印**；"只校验格式"的分支必须被移除或降级为 WARN。
- **状态**：候选（未入库）

## CM-3 可执行性分层模型（来源：3-LEARNED 1.69）

- **名称**：可执行性分层模型（Executability Layering Model）
- **版本**：候选 v0
- **模型描述**：同一段文本有**三层**存在形态——**非执行文本**（注释/日志标签/here-string/变量赋值）、
  **可执行位置**（命令行首的解释器/调用形态）、**已提交事实**（CI 按提交范围复核）。
  判定"某机制是否接线/是否生效"只能认**第二层及以下**；用第一层满足判据 = 把判据变成恒真式。
  对应的反向对照必须是"**删真调用、留标签**"这类**按行**注入；**全局文本替换的对照视为未做对照**。
- **使用时机**：一切接线类判据（CI 是否调用某闸门、钩子是否装载、安装器是否装钩子、
  配置项是否被消费）；也适用于"这条规则有没有执行点"的盘点（`A-M11` ② 的核心问句）。
- **模型边界**：判"有没有真的跑"，**不判**"跑得对不对"（后者是另一模型的问题）。
- **输入**：待检文件集 + "被检机制的可执行形态"白名单。
- **输出**：命令位置命中行 + 按行反向对照的证据（删真调用后仍红）。
- **模型创始人**：本项目（源事故：`verify_gate_integrity.py` 的接线判据用全文 `re.search`，
  而 `ci.yml` 里有一行同名 `Write-Host` 标签 ⇒ 删掉真执行行、只留标签，判据仍返回零问题）。
- **来源**：`docs/3-LEARNED.MD` **1.69**；机制反例档案例（`087-major-1` 原形态）。
- **成功判据**：能生成一个 workflow：对被检机制做"删真调用/留标签"注入，判据**必须变红**；
  若不变红则该 workflow 自身不成立。
- **状态**：候选（未入库）

## CM-4 隐含前提前置族模型（来源：3-LEARNED 1.31 再版注记）

- **名称**：隐含前提前置族模型（Implicit-Premise Families）
- **版本**：候选 v0
- **模型描述**：凡"本地成立、换环境/换分支就不成立"的隐含前提，可分为**四族**：
  **①版本族**（依赖推导、工具版本）、**②系统二进制族**（Graphviz 等）、
  **③环境变量族**（`PYTHONOPTIMIZE`/代理/区域设置）、**④路径族**（只在某分支存在的目录树）。
  新增任何判据/夹具时，必须逐族回答"它在**每个承接环境**下是否成立"；
  **路径族**是本项目最近一次复发的那一族（main 上不存在 `docs/iteration/**`）。
- **使用时机**：新建闸门/自检夹具/CI 步骤、"本机能跑"的验收结论、跨分支同步前的自查。
- **模型边界**：只管**前提清单**的完备性，不管"某族前提的具体取值"；四族之外出现新族时应**扩族**
  （扩族本身是需要留痕的动作）。
- **输入**：新判据/夹具/CI 步骤 + 承接环境清单（本地 windows / main 形态 / 冷 runner）。
- **输出**：四族逐族的"成立/不成立/不适用"判定 + 由路径族派生的条件根声明
  （`md_table_coverage.conditional_roots` 这类）。
- **模型创始人**：本项目（源事故两次：Sprint-9 CI 首跑三坑；Sprint-18 关闭二查 `088` 三条 critical
  ——新闸门拿 windows-only 路径当前提，落 main 必红）。
- **来源**：`docs/3-LEARNED.MD` **1.31**（含 2026-09-26 再版注记）；`088` 的基线对照证据。
- **成功判据**：能生成一个 workflow：对每族前提产出一条**可执行**判定（存在性检查/版本断言/
  环境剥离），且路径族判定必须在**每个承接分支的树上**跑出同一结论。
- **状态**：候选（未入库）
