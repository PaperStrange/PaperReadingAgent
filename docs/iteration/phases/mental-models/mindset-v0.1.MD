## 0. 本文件是什么／不是什么

**是**：MM-6 的设计交付——定义「思维实验」在本仓四个阶段里的**触发场景、展开步骤、输出形态、失败判据**，并给出**只用一步就能开始用**的落地。

**不是**：模型库 schema（MM-1）／模型→spec 生成器（MM-2）／`agents/functions/thought-experiment.md`（MM-3）／3-LEARNED→候选模型提取 SOP（MM-4）／自适应触发扩展（MM-5）。逐条边界见 §5。

**两个容易混的对象**（本文件的分工依据）：

- **模型**＝可复用的思考方式（如种子模型「对一个问题生成不少于三种方案并模拟」）——描述它、入库、生成 spec 属 MM-1/MM-2/MM-3；
- **记录**＝某一次思考的留痕（这一次的问题、路径、反例、判决）——**本文件只管记录怎么长出来、怎么被拒绝**。

**「生产环境」的定义（本文件的关键限定）**：不是部署环境，而是**结论会被别人消费、错了要付代价**的作业面——用户走查与验收、跨会话交接、方案讨论与拍板、对外汇报。工程环境（本地跑通、单测绿）只是它的一个子集。

**本文件不新增强制规则**：它定义的字段与判据只约束「用了这个工作方式的记录」，不约束没用的场景；是否升级为强制规则属 G3／后续卡，v0.1 不处理。

**旁证（非条目编号，但同一病灶）**：`3-LEARNED.MD` 头部「改本文件之前必读」义务块自陈——2026-09-26 追加 `1.67`~`1.69` 时**没有执行义务 1（MM-4 提取）**，次日由用户指出。它证明的不是「谁粗心」，而是**义务只活在「我记得」里时，它就不是机制**。

### 1.2 病灶：三条输入症状的共同结构

MM-6 的输入是 Sprint-16 走查暴露的三件事（卡面原文，`[用户插入]` 2026-09-20）：**规范已写但未执行 / 过程不可见 / DoD 偏代码层**。

- **规范已写但未执行**：本仓已登记为卡 [`A-DECL`](../agents-infra/cards/A-DECL.md)——「规则可以是没有实现的声明」；实例是日期口径规则 `1-WORKFLOW.MD:403` 在全仓零实现。
- **过程不可见**：`1.67` 的损坏不是被闸门抓到的，而是**事后肉眼**发现的；判决只存在于会话里时，换一个会话就等于没发生过。
- **DoD 偏代码层**：验收判据能回答「测试绿不绿」，回答不了「这个方案当时为什么被选中、什么情况下它会被推翻」。

三条的共同结构只有两个：

1. **思考的产物是「结论句」，不是「可被判定的对象」**——没有反例、没有判决、没有适用环境，于是它既不可复核也不可反驳；
2. **结论的有效期与适用范围没有写在产物里**——同一句话在工程环境成立，被搬到验收／汇报就变成了过度承诺（`1.73` 的同族）。

### 1.3 本设计押的注（可被否证）

押注：把思考落成**固定字段的记录**（路径／事实／反例／判决／未验证），能让决策事后可复核、记录可被 agent spec 消费、形式主义可被一条判据拦住。

**否证条件**（任一成立即 v0.1 失败，不辩解）：

- ① 第 2 份记录无法在**不读会话**的情况下复核；
- ② 记录字段与 spec 的 `Task Input` / `Output Template` 对不上，MM-2 无法映射；
- ③ §6.2 判据在真实记录上放过了一份「有结论、无反例」的记录；
- ④ 记录只增不读——后续卡、提交信息、spec 三处**零引用**。

## 2. 「思维实验」的操作定义

### 2.1 定义句

一次思维实验 ＝ 对一个**已冻结基线**的待决问题，生成**不少于三条互斥路径**，对每条路径做**事实/推断分离**的推演，为每条路径写**可取得判决的反例**，**真取判决**（取不到则标未验证），最后给出**带采纳条件的建议**。

一句话判据：**没有反例的推演是评论，没有判决的结论是主张。**

### 2.2 输入（触发场景 → 材料 → 约束）

| 输入项 | 必填 | 形态与判据 |
|---|---|---|
| `trigger` | 是 | 四阶段之一＋具体入口：`agents/fanout.json` 的 step 名／卡号／走查轮次／卡内决策点。写「讨论时」不算触发。 |
| `question` | 是 | 一句**可判真假**的命题（「应…／不应…」或「A 还是 B」）。写「如何做好 X」不是命题。 |
| `baseline` | 是 | 已裁决项清单，每条带决策号或 `path:line`；**空也要显式写「无既定基线」**（空是一种内容，不是省略）。 |
| `material` | 是 | SSOT 指针＋命令（`1-WORKFLOW.MD` §6：派生数字只给复现命令，不手抄读数）。 |
| `constraints` | 是 | 时间／范围／不可动项（例：不改 `agents/fanout.json`、不动 `agents/policy.json`、不新增文档类型）。 |
| `freeze` | 是 | 判定时点＝网络日期＋当时的 sha 或 run id；它决定「这条判决属于哪一版」。 |

### 2.3 展开步骤（S1–S6：可执行的思考动作）

| 步骤 | 可执行动作 | 产物字段 | 完成判据 |
|---|---|---|---|
| **S1 定题与冻结基线** | 把待决问题写成可判真假的命题；从 `docs/6-DECISIONS.md`、预研已拍板项、`1-WORKFLOW.MD` §4.4 取出基线（带决策号或 `path:line`）；标 `freeze`。 | `question`／`baseline`／`freeze` | 命题能被回答「是/否」；基线每条有指针；若问题已被生效裁决覆盖 → **停止**，改走翻案建议。 |
| **S2 列互斥路径（不少于三条，含维持现状）** | 每条路径＝动作集＋依赖事实＋预期可观测结果；**强制一条「维持现状／不做」**；用「选择点」证明互斥（改的是哪个参数／哪个文件／哪张卡）。 | `paths[]`／`选择点` | 选择点可枚举；至少两条路径改的是**不同参数**；否则判 F1。 |
| **S3 事实与推断分离** | 逐条 `claim` 标 `fact`／`inference`；`fact` 必须带指针（`path:line`／命令／判决对象 id）；`inference` 必须写依据的机制＋为何在此适用。 | `claims[]` | 无指针的 `fact` 一律降级为 `inference`，不得当论据（预研 §2.4 边界④：不得编造未证实的作用机制）。 |
| **S4 逐路径推演＋反例** | 按「动作 → 可观测中间态 → 与预期比对」逐段写；每段至少一个可观测判据；每条路径写 `falsifier`：什么观测会推翻它＋取得该观测的**最便宜动作**。 | `simulation[]`／`falsifier` | `falsifier` 必须落到「一条命令／一次读文件／一个判决对象」；「理论上可能失败」不算（判 F3）。 |
| **S5 取判决（三态）** | 真跑探针；记录 `系统＋标识符＋判决＋rc`；取不到就写 `未验证（原因：缺环境／缺权限／缺数据）`。 | `verdicts[]`／`判决证据` | 每条路径的 `verdict` 属于 `PASS`、`FAIL`、`未验证` 三者之一；未跑写成 PASS 判 F4。 |
| **S6 收敛与采纳条件** | 写排序键（代价／可逆性／证据强度，各自取值来源）；给建议；写**采纳条件**（若 X 则 A，否则 B）；列未验证项与下一次触发点。 | `排序`／`建议`／`采纳条件`／`未验证项`／`adoption` | 建议能被主代理／人在**一次裁决**里落成 `6-DECISIONS.md` 条目或卡 `## 交付`；不能落地的建议不算输出。 |

> 六步不是六个工作项：S1–S6 是**同一件事**的展开顺序，写在一份记录里（骨架见 §2.4）。

### 2.4 输出：可被 agent spec 消费的结论形态（记录骨架）

记录 id 前缀 `TE-`（thought experiment）；下面是骨架，字段名即下游可寻址的位置。

```markdown
# TE-<网络日期>-<slug>
- stage: design | dev | retro | acceptance
- trigger: <step 名 / 卡号 / 走查轮次 / 决策点>
- question: <可判真假的命题>
- baseline: <决策号 / path:line>；空则写「无既定基线」
- freeze: <网络日期 + sha 或 run id>
- material: <SSOT 指针 + 命令>

## 路径
### 路径 A：<名称>
- 动作集: <做什么>
- 选择点: <与 B/C 不同在哪个参数>
- 依赖事实: fact: <...> [path:line]；inference: <...>（依据：<机制>）
- 推演: <动作 → 中间态 → 预期>
- falsifier: <观测 + 取得动作（命令/读取）>
- verdict: PASS | FAIL | 未验证（<原因>）
- 判决证据: <系统 + 标识符 + 判决 + rc>

### 路径 B：<名称>
### 路径 C（维持现状）：<名称>

## 收敛
- 排序键: <代价/可逆性/证据强度，各自的取值来源>
- 建议: <...>
- 采纳条件: 若 <X> 则 <A>，否则 <B>
- 未验证项: <逐条，带原因>
- adoption: <采纳/否决 + 裁决人 + 网络日期>
```

**三条消费约束**（记录能被下游直接吃，不靠口头解释）：

- **C1 字段自足**：不读会话也能复核（`question`／`baseline`／`material` 自带指针）——对应 `1.68`「输入必须显式传入或连来源打印」；
- **C2 判决有对象**：`判决证据` 必须是「系统＋标识符＋判决＋rc」，不是「应该会通过」——对应 `1.70`；
- **C3 未验证显式**：「未验证」是合法终态，**不折叠成 PASS、也不当成 FAIL**——对应 `1.72`／`1.73`。

**与 spec 的接口位置**（只指位置，不做映射——映射与生成器属 MM-2）：

- `question`／`baseline`／`material`／`freeze` → 某 spec 的 `# Task Input`（模板：`agents/functions/_template-agent.md`）；
- S1–S6 → `# Steps`；记录骨架 → `# Output Template`；F1–F6（§2.5）→ `# Forbidden`。

### 2.5 失败判据（何时给出无效结论）

| 编号 | 触发条件 | 判定 | 处置 |
|---|---|---|---|
| **F1** | 互斥路径少于三条，或三条是同一参数的变体（假选择） | 无效 | 补路径或改题；不得用「A／A改／A再改」凑数。 |
| **F2** | 结论依赖的 `fact` 没有可核指针 | 无效 | 该 `fact` 降级为推断；结论若仍依赖它即整份无效。 |
| **F3** | 任一路径没有 `falsifier`，或 `falsifier` 不可取得 | 无效 | 该路径不得进入排序；整份记录标 `无效（F3）`。 |
| **F4** | 判决只有「应该／我认为」；未取判决且未标未验证 | 无效 | 按 `1.70`：发出动作 ≠ 取到判决；补探针或标未验证。 |
| **F5** | 已拍板基线被静默重议（`1-WORKFLOW.MD` §4.4） | 越权，无效 | 改走「翻案建议」形态，显式列出基线条目与推翻理由。 |
| **F6** | 结论只在工程环境成立，却被用于验收／讨论／汇报 | 该环境未验证 | 按 `1.73` 给具名第三态；不得作为对外结论。 |

**无效的处置（重要）**：记录**保留**并标 `无效（F#）`；不得作为任何裁决／交付的依据；**不得静默删除**——删除会让「这次没有结论」这个过程再次不可见。

**「无效」不是失败**：无效＝这次实验没有产出可消费结论；失败＝某条路径的判决是 `FAIL`。两者都可存档，都可用于复盘。

## 3. 与四阶段的关系

按生命周期排序（卡面写作「开发／设计／复盘／验收」，同名不另立）。每行只回答三件事：**嵌在哪个真实入口**、**谁执行**、**留下什么记录**。

| 阶段 | 嵌入的真实入口 | 执行者 | 留下的记录 | 该阶段特有的失效形态 |
|---|---|---|---|---|
| **设计** | `planning_pipeline.research`（`agents/fanout.json` order 1）／预研 §3 的 Q 项／卡内方案选择 | 子代理（expert/scholar 深度）或主代理（quick）起草 → 主代理裁决 → 人拍板（预研 §3 的 Q 项就是这种形态） | 预研笔记（`docs/iteration/pre-research/<domain>/`）＋`docs/6-DECISIONS.md` 条目 | 预研 Q 项历史上多为「A vs B」二选一、缺 C＝维持现状 → 假选择（F1）；「讨论过」当成「裁决过」（F5） |
| **开发** | 实现前选型（技术路径／机制形态）＋提交前自检；变更执行可派 `implementation` 子代理（其 spec 明确「只改不判」） | 主代理裁决选型；变更由 `implementation` 子代理执行并留证据 | 卡 `## 交付`＋提交信息＋`agents/runs/<run_id>/implementation.report.md` | 先写码后补理由（事后叙事）；把「能跑」当「选对了」；判据看不见被改对象（`1.67` 同族） |
| **复盘** | `sprint_close_pipeline.lessons`（order 4，`lessons-learned` 子代理）→`docs/3-LEARNED.MD`；经验增量提取（MM-4） | 子代理起草 → 主代理回填（`lessons-learned` spec 明确禁止直接改 3-LEARNED） | `3-LEARNED` 条目＋`models/<日期>-from-learned-*.MD`（MM-4） | 只写现象不写可复用规则（spec 已禁「下次小心」）；复盘＝总结；未验证项在复盘时被静默丢弃 |
| **验收** | `impact-assessment`(1) → `doc-audit`(2) → `code-review`(3) → `workspace-check`(5，主代理执行、不派单）→ 用户走查 | 子代理（1–3）→ 主代理（5）→ 人（走查裁决） | `agents/runs/<run_id>/<role>.report.md`（含 scope／覆盖窗口）＋`verify/verify_close_readiness.py` 判决行＋走查记录（Sprint 文档） | 「推完了」当「判过」（`1.70`）；证据只在会话里（过程不可见）；只在工程环境成立却对外汇报（F6） |

**讨论与汇报不是第五阶段**：它们是「验收」的对外呈现面。规则只有一条：对外结论必须带「系统＋标识符＋判决」三元组和未验证项；缺任一项按 F4／F6 判无效——这正是 `1.70` 的「没判」被洗成「判过」的入口。

**每阶段只「嵌入」不「新增仪式」**：设计阶段用它替代「直接给一个方案」，验收阶段用它替代「我觉得可以」；不新增会议、会议纪要或文档类型（记录落点由 §4 的第 1 份记录判决）。

## 4. 最小可行落地 v0.1

### 4.1 只做一件事

**下一步只做一件事：产出第 1 份真实记录，主题固定为「思维实验记录落在哪里」。**

三条真实互斥的路径：

- **A 集中**：`docs/iteration/phases/mental-models/experiments/`；
- **B 分散**：按阶段落进各自既有载体（设计→预研、开发→卡、复盘→3-LEARNED、验收→run report）；
- **C 不建文件**：附在卡的 `## 交付` 一节。

为什么先做它（四条理由，都可核）：

1. 它是所有后续记录的**前置**：没有落点，第 2 份记录无处安放；
2. 三条路径**真实互斥**（改变的是「文件在哪」这一个参数的不同取值），不是措辞变体；
3. 判决可由**命令**取得（枚举全部记录、是否被 `.gitignore` 覆盖、是否被 `verify/verify_md_tables.py` 扫描），不需要新平台；
4. 它验证方法本身（self-hosting）：一份关于「记录该放哪」的记录，正好检验骨架是否够用。

### 4.2 具体动作（同一件事的执行顺序，不是六个工作项）

**执行者**：主代理起草与裁决（可派子代理并行填某条路径的推演，但 `adoption` 必须由主代理写）。

1. 在 `docs/iteration/phases/mental-models/experiments/` 下用 §2.4 骨架写 `<网络日期>-record-location.md`。**代价（如实记）**：这份记录本身必须先有落点，所以先按 A 暂存——这是唯一不需要预先裁决的做法；若最终判决是 B／C，迁移这份记录、删掉空目录，并留下迁移说明（迁移本身也是「判决被执行」的证据）。
2. 填 A／B／C 三条路径，每条写选择点、依赖事实、推演、`falsifier`。
3. 跑 A／B／C 各自的 `falsifier` 探针取判决（例：枚举命令、`git check-ignore` 退 0、`verify/verify_md_tables.py` 是否扫描到），把 `verdict` 与 `判决证据` 回填；记录的结构再按 §6.2 自检。
4. 主代理在 `adoption` 写「采纳／否决＋理由＋网络日期」。
5. 下一张进入执行的卡（MM-1 或 MM-2）在 `## 交付` 里**引用这份记录一次**（路径＋一句话），作为「有人消费」的证据。

| # | 退化形态 | 触发条件 | 早期信号 |

| 1 | **事后叙事** | 记录在决策之后补写，只为「留痕」 | 「预期结果」写得比实际还准；记录日期晚于提交日期 |

### 6.2 一条可检验判据（本文件的核心防线）

**判据**：任一份 TE 记录，`### 路径` 的数量必须等于 `- falsifier:` 的数量，且不存在「裸 falsifier」（以「理论／可能／也许／待补／TODO／不可执行」开头）；否则整份记录判 `无效`，且**不得被任何裁决或交付引用**。

**为什么是这条**：它把 `A-DECL` 的病（规则可以是没有实现的声明）搬到记录层——「这条路径可能失败」正是一句**没有实现的声明**；`falsifier` 必须指明「用什么动作能取到失败」。这也是 `1.67` 的教训在记录层的形态：判据要看得见被判定对象。

**命令**（PowerShell，v0.1 为 manual；读数以命令输出为准）：

```powershell
$f = 'docs/iteration/phases/mental-models/experiments/<网络日期>-<slug>.md'
$paths = @(Select-String -Path $f -Pattern '^### 路径' -Encoding utf8).Count
$fals  = @(Select-String -Path $f -Pattern '^- falsifier:' -Encoding utf8).Count
$naked = @(Select-String -Path $f -Pattern '^- falsifier:\s*(理论|可能|也许|待补|TODO|不可执行)' -Encoding utf8).Count
"paths=$paths falsifiers=$fals naked=$naked"
if ($paths -ne $fals -or $naked -ne 0) { '无效'; exit 1 } else { 'PASS' }
```

**它自己的失效形态（如实记）**：正则只认行首格式，记录可以写「falsifier（不可执行）：…」绕过——`naked` 正则已覆盖「不可执行」，但同义改写（如「仅作参考」）仍可能漏；v0.1 不建闸门，剩余风险靠验收时的评审 agent 抽查。**这条判据是「可检验」，不是「已机检」**，与 §4.4 的 `manual` 声明一致。
