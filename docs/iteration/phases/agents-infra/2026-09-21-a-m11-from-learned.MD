## 判定标准

**正式口径（Round 2 拍板）**：**该条教训的"持久化修复动作"若是规则 / 检查点 / 工具层 / 提示词 / 流程 → 属 A-M11 域；若是代码 / 库 / 平台 / 第三方 → 非本卡（技术类）**。理由：本卡交付物是"纪律 + 闸门"，要看"要落地什么动作"，而不是看当初那起事故属于哪一类技术。

**三类结论**：

1. **属于（强）** —— 持久化修复动作本身就是规则 / 检查点 / 工具层 / 提示词 / 流程。
2. **属于（弱）** —— 条目的技术修复主体是代码，但其自陈的"教训"里含**必须固化的规则 / 检查点 / 提示词 / 流程**（即"A-M11 只接手纪律侧，代码侧仍归各自技术卡"）。对应 Round 1 的"属于（部分）"，共 12 条。
3. **不属于** —— 持久化动作只有代码 / 库 / 平台 / 第三方，标 `非本卡（技术类）` + 一句话理由。

**已被其他卡覆盖** —— 标注覆盖卡号（`TG-11`/`TG-12`/`TG-8`/`TG-9`/`TG-6`/`TG-10`/`TG-5`/`TG-7`/`M6`/`A-PM4`），并区分：**已落地（完全/部分）** vs **待 X 落地（当前未覆盖）**——凡卡状态为"候选/计划中"的，一律不得写成"已覆盖"。

**子目标类别**：

| 类别 | 含义 |
|---|---|
| **C1 规则无执行点** | 规则只有文字、没有闸门/检查点（对应 TG-11 结论"有规则 ≠ 有执行点"） |
| **C2 验证不可靠** | 假绿、形态漏检、只在本地/单路径验证过、断言环境依赖、自检负例不命中真实失效模式（细分见 C2a/C2b） |
| **C2a 无检查点** | 压根没有检查——缺陷靠人发现或靠事故暴露 |
| **C2b 有检查点但不可信** | 检查点存在但骗人：假绿 / 形态漏检 / 负例不命中真实失效模式 / 只在本地验证过 / 断言环境依赖 |
| **C3 可观测性/账本失真** | 看不出被中断、时长产出低估、静默失败、错误被掩埋、「停止」语义失真 |
| **C4 破坏性操作与内容丢失** | 误删/丢弃/静默少内容/静默覆盖/并发写丢失 |
| **C5 文档与口径漂移** | 同一事实多处副本、状态陈旧、日期与数字口径不一致 |
| **C6 规则检索不到/分类错误** | 规则挂在"阶段"而非"动作"、任务分类先于规则检索、既有标准/机制/真源在动作点未被找到 |
| **C7 多代理协作与派发纪律** | 报告先行、超时接管、prompt 零漂移、scope 来源、职能粒度 |
| **C8 成本/预算纪律** | fail-open、未测量当已测、估算偏差、口径混算 |
| **C9 其他 agent 行为类** | 自行判断，需说明 |

**C6 命中测试（Round 2 补扫用）**：条目中存在某个**已存在的规则 / 契约 / 标准 / 既有实现 / 登记处 / 权威真源**，在执行动作时**应当被找到并使用**，而实际**没被找到 / 没被使用 / 被挂在了检索不到的位置**。真源须是**可检索物**（文件、规则、标准、登记处、查价表），单纯的"该做而没做的探测动作"不计入 C6（归 C2）。
