# 治理六层地图（2026-09-29）

> 归属：`docs/iteration/phases/agents-infra/`。作者：主代理。**成因**：用户 2026-09-29 提问
> 「现在你是怎么管理规则、决定、反例等等」——本文是那次回答的**落盘版**，不是新方法论。
> **时效声明**：文内计数是 **2026-09-29 最近一次现跑读数**，会随编辑变化；引用时必须带时点锚。

## 0. 一句话

这套治理不是「一套流程」，而是**六层各管一件事、靠链路串起来**的产物；
**每层都有「真机制」和「只是文字」两部分**，把后者误当后者是这套体系最大的自欺来源。

## 1. 六层

| 层 | 载体（真源） | 管什么 | 真机制（可机检） | 只是文字／口径 |
|---|---|---|---|---|
| ① 规则层 | `docs/1-WORKFLOW.MD` §6（编号 **1–19**） | 以后怎么做 | `verify_gate_integrity.py`（守卫调用结构、rc 是否进终判）；编号连续性可 grep | 大部分规则**靠人执行**；规则可以是「无实现的声明」（见 `:403` 日期口径，2026-09-29 按裁定就地降级为**未验证口径**） |
| ② 决定层 | `docs/6-DECISIONS.md`（D- 逐字原话 ＋ V- 裁定） | 你说过什么、据此定了什么 | `verify_decision_register.py`：逐字引文须在指针 ±2 行内命中（最近读数 122 条／1248 指针／漂移 10） | 指针是 **`path:line`** ⇒ 每次插入 `docs/**` 都漂（2026-09-29 一天撞 **4 次**）→ 卡 `A-PTR` |
| ③ 反例层 | `agents-infra/*-case.MD`（派单 1–12、闸门机制 1–26 等） | 错在哪、代价多少、怎么复用 | 目录存在性与引用；`verify_card_index.py` 只管卡 | **实际损失**只能从会话日志反推（账本 99 条 run 仅 **8** 条带 `usage`）→ `A-COST`；语料只增不减 → `A-CASE` |
| ④ 运行层 | `agents/runtime/registry.json` ＋ `scripts/agent-ops.py` 受控口 | 谁在何时做了什么、覆盖到哪 | `verify_close_readiness.py`（C3 归属、§9 linkage）、`verify_ledger_measurement.py`（以现跑末行为准） | **分不清谁按的键** ⇒ 规则 14「派单方登记 run」不可验证 → `A-REG` |
| ⑤ 度量层 | `scripts/spend-report.py` ＋ `agents/spend-budget.json` ＋ 规则 17 | 我自己花了多少、有没有超 | `--check` 自检（超预算 rc=1；配置会话全不匹配 ⇒ **SKIP 不是 OK**） | 预算**不是闸门**（不阻断流程）；模型名是假设（事件里无模型字段） |
| ⑥ 关闭层 | 复盘 §5 findings 表（**唯一状态真源**）＋ `verify_close_tax_reading.py` | 还剩什么没闭环 | 关闭税机读 `critical/major/doc_items`；`D-250926-06` 零未闭环项 | **「只报」不是豁免**——只能靠口径段约束，闸门判不出语义 |

## 2. 链路

**事故／用户的话 → ③案例（现象＋证据＋实际损失）→ ①规则（引案例号）→ ②决定层（逐字＋指针）
→ 闸门（能机检的部分）→ ④账本（执行留痕＋覆盖窗口）→ ⑥§5（关闭状态）→ 关闭税读数**

**反向也走**：⑥§5 的未修行 → 派修复批 → ④账本记实现 run → ⑥翻状态。

## 3. 已识别的弱点（2026-09-29，均已拆卡）

## 4. 未覆盖（本文不声称已覆盖）

- **克隆内验证**：本机系统级 `core.autocrlf=true`，任何 `git clone` 默认 CRLF ⇒ 与 CI 不等价（规则 18）；本文各层均未在克隆内全量复验。
- **`gui`／`network`／`e2e` 档**：本文读数全部来自 `--tier offline`。
- **闸门覆盖 ≠ 规则覆盖**：有闸门的规则不等于被执行，没闸门的规则不等于不重要（见 `A-DECL`）。
