**层位判定（本卡的核心问句"harness 管的是哪一层"）**：harness 解决「**一个会话内部**如何可靠跑 agent loop」（thread/turn/item 生命周期、沙箱、审批、鉴权、hook 点）；**不解决**「哪个角色、在什么条件下、按什么顺序、产出什么、是否合格」。与 `agents/fanout.json` **既不重叠也不互补**（官方定义里没有"流程"概念；456 行 app-server 协议的 20+ 变更节全在会话/信任/鉴权/网络策略/审批/回滚）⇒ 用会话模型表达跨 run 流程 = **层级错配**。与 `agent-ops` 账本的重叠面仅"会话登记/恢复"；互补面（**提交级覆盖窗口**与**关闭必填步骤**）harness 不表达 ⇒ 净收益 = 重叠 − 迁移成本 − 绑定风险 = **负**。与 `verify/*.py`：hook 在 Stop/SubagentStop 跑校验，**位置上等价**；而 `PostToolUse` 的 block 官方明示**不能撤销已发生的副作用** ⇒ 同属事后能力类别，**不带来能力升级**，只带来更早触发。

**三条最强证据（含 verbatim；完整段落见 evidence/）**：
1. `https://code.claude.com/docs/en/memory.md`（tier1）——"Claude treats them as context, **not enforced configuration**. To block an action regardless of what Claude decides, use a PreToolUse hook instead."
2. `https://learn.chatgpt.com/docs/customization/overview.md`（tier1）——"Pair `AGENTS.md` with infrastructure that enforces those rules: pre-commit hooks, linters, and type checkers catch issues before you see them"
3. `https://web.archive.org/web/20260904044950/https://openai.com/index/unlocking-the-codex-harness/`（tier1 存档）——"they're all powered by the same Codex harness—the agent loop and logic that underlies all Codex experiences"

**结论一句话**：**两家官方都明示"提示词层没有强制力"**（证据 1、2）⇒ 方向 ①（分层提示词）只能**降低复发率**，不能**消除**擅自行动；真正的判红仍在闸门层。
