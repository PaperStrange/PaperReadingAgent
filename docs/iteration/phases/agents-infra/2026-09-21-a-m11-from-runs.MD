### 1.2 时间口径

- **主口径：2026-09-21（UTC+8）**。
- **已实测的时区事实**：`agents/runs` 里的 `run_id` 日期一律按 **UTC+8** 命名，而 `registry.json` 的 `started_at`/`ended_at` 一律记 **UTC**。两者系统性错开：`run-2026-09-21-*` 的 6 个 run 全部 `started_at = 2026-09-20T17:2x~17:50+00:00`（UTC+8 的 09-21 01:2x~01:50）。全库 **12 个 run 的 `run_id` 日期 ≠ `started_at` 的 UTC 日期**（`run-2026-08-30-tech-research-013`、`run-2026-08-31-*` 五个、`run-2026-09-21-*` 六个）——**这是命名约定，不是记录错误**，但解读账本时必须先做一次 +8 换算，否则会把 09-21 的 run 误读成 09-20（见 §2 `E-13`）。
- **另有本机时区 ≠ 项目时区**：多份 09-21 报告自述"本机 UTC+9，项目权威 UTC+8"（`run-2026-09-21-doc-audit-055:7`、`run-2026-09-20-code-review-053:4`），且已有工具因此出 bug（见 §2 `E-14`）。

### 1.3 纪律

- 每条事件**必须**给 `run_id` 或 `文件:行`；读不到就写"未读到"。
- 不美化、不推断运行时行为；报告自身标"疑似"的，本文保留"疑似"。
- 数值结论一律给**复现命令或脚本口径**，不凭记忆。
