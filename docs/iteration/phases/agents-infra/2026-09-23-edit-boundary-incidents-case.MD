# 编辑边界事故族（"表格行/标题被吞"）—— **测试反例**（agents-infra 阶段）

> 归属：`docs/iteration/phases/agents-infra/`（体例与 `2026-09-23-subagent-scope-breach-case.MD` 一致：一个题族一文件，**不并入任何卡正文**）。
> 性质：**本仓库独有的执行层失效族** —— 不是"内容漂移"（那是 `TG-12`），不是"规则绕过"（那是 `TG-11`），
> 而是**编辑动作本身把边界内容吃掉**。Sprint-17 内实测 **5 次**，全部发生在 Markdown 表格/标题的邻近编辑上。
> 落盘日期：2026-09-25（UTC+8）

## 1. 可核事实（5 次occurrence，按 §10 的 R1 记录）

| # | 日期 | 越界/吞掉的东西 | 触发动作 | 发现方式 | 修复 |
|---|---|---|---|---|---|
| R1-1 | 2026-09-23 | `backlog.MD` 的锚点行 `## 2. 启动条件`（整行标题消失） | `edit` 以"锚点行"作替换边界 | 替换后立即 `read` 复核（30 秒内） | 补回标题 + 表格结构复测 |
| R1-2 | 2026-09-23 | `1-WORKFLOW.MD` 下一节的粗体标题整行消失 | 插入新节时 `old_string` **取了下一节首行** | 插入后立刻 `read` 该区间 | 补回标题 + 保留原句 |

**共同形态**：`old_string` / 脚本替换范围**跨到了"我以为是边界、其实是内容"的位置**——标题行、表格行首、单元格分隔符。

## 2. 为什么这是"反例"而不是"我不小心"

三次 R1 与两次同型事故**全部由自检在 30 秒内发现，没有一次靠肉眼**。这说明：

1. **"更小心"不是对策**——5 次里我能记得的注意力都用了；失效点是**动作的假设**，不是注意力；
2. **检测已经有效**（`verify_md_tables.py` + 一次性列数自检抓住了 5/5），缺的是**预防**：目前没有任何东西在**写入前**拦住跨边界替换；
3. 因此它可当**回归样本**：任何未来的"编辑安全"改进都必须能对**这 5 个形态**给出 FAIL→PASS 的对照。

## 4. 待补护栏（本反例的直接产出，供 A-M12 落地）

1. **规则**：插入/替换 Markdown 结构时，`old_string` 只能取**上一节的尾行**或**被插入位置之前的整行**；
   **禁止**取"下一节首行""表格行首""单元格边界"；需要跨行改动时**走脚本**而非 `edit`；
2. **预防机制（比规则强）**：一个"写入前预览"式的检查——对 `edit` 的 `old_string` 做**边界体检**
   （是否包含行首 `|`/`#`/表头分隔行），命中即拒绝并要求改用脚本；
3. **检测扩展**：把 `verify_md_tables.py` 的判据扩到**标题层级**（相邻标题缺失/重复）——补上 R1-1/R1-2 的盲区；
4. **每条护栏都必须对 §1 的 5 个形态给出反向对照**（先证明旧实现会 FAIL）。
