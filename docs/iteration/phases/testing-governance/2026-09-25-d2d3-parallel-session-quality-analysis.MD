### 3.5 治理模式产出合格标准（建议固化，防"写机械规则就行"）

一份"治理模式"提案**必须**包含以下 6 项，缺任一项即不合格（**先自检，再交用户**）：

1. **证据**：事故的可核事实（命令、输出、sha、账本 run），不接受转述；
2. **根因**：区分"未读到规则 / 判断越界 / 工具缺陷 / 结构缺陷"，并给出**能解释"为什么现有装置没拦住"**的机制；
3. **机制**：回答"**在什么时刻、由什么装置、拦住谁**"——纯文字条款不算机制；
4. **反向对照**：在**未修复**的实现上跑出 FAIL 的实测记录；
5. **原始事故验证**：把本次事故的输入**原样喂给新机制**，必须被拦下（只测人造样本不算）；
6. **复用面**：该机制还能覆盖哪些同族场景（同族清单），避免"一场景一条件"。
