`[用户插入]` **闸门可信化收尾：覆盖窗口语义 + C1 判定域**（来源＝`TG-15` 独立复核批的两条 finding，用户 2026-09-23 批准开卡）：**问题① 覆盖窗口结构性为空**——`TG-15` 的"锚点自动化"让每个 run 记 `(coverage_anchor, covers_through]`，但 `register` 记登记时 HEAD、`finish` 记收尾时 HEAD，而关闭三查各步常在**同一 HEAD** 登记/收尾 ⇒ 窗口恒为 `(X, X]` = 空集。实测证据：账本 `run-…-impact-assessment-062` 的 `coverage_anchor == covers_through == e6ccd257…`；`092a2f7..HEAD` 的 9 个提交里 **6 个 UNOWNED**，自动窗口贡献 **0 覆盖**，C3 压力全落到 C3-T 例外表（而例外表 sha 钉死、按设计只能登记例外，不该承担主路径）。**问题② C1 判定域＝全账本**——账本 60/63 条历史 run 无 `scope_source` 键（`TG-11` 之前的 run 本就没有该字段），现判据把"凡 `scope_required: true` 的 run 都要有 scope 声明"施加到**全部历史** ⇒ 真数据上 `verify_close_readiness.py` **永久 FAIL 34 条**，闸门退化为噪音；且账本有完整性哈希（`_integrity`），无法手工补字段回填历史。**共同根因**：判据写成"无条件的全域断言"，而语境是"本次关闭窗口"——空输入与历史数据都会让判定失去意义。
