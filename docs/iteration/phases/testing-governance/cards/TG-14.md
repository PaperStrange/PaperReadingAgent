**追加判据（与 ④ 同族，纳入 `verify_card_index.py` 或同批 lint）**：
1. **每份治理/分析类文档必须在头部声明一行机器可读的关系**，例如
   `> 关系：supersedes=…|derived-from=…|input-to=…|详见=…`（键取自固定白名单；缺行即 FAIL，白名单外键即 FAIL）；
2. **闭环校验**：所有 `supersedes/derived-from/input-to` 指向的路径必须存在，且**反向关系必须成对**（A 声明 `input-to=B` ⇔ B 声明 `derived-from=A`），否则 FAIL 并点名缺失的一侧；
3. **无孤儿/无环**：每份这类文档至少被一条关系链连到某个索引（卡/backlog/roadmap/Sprint §7），且关系图**无环**（`supersedes` 链尤其不得成环）；
4. **被取代稿**：必须显式 `superseded-by=<权威稿>` 且权威稿反向 `supersedes=<旧稿>`（现有横幅文案保留为人类可读部分）；
5. **反向对照**：删掉一端的声明 / 伪造指向不存在路径 / 造一个环 → 必须 FAIL 点名。
6. **呈现**：并入 `TG-16`（审查流程与策略全景 HTML）——由关系声明**自动生成**关系图（因果链 + 取代链 + 阅读顺序），**不手工画**（手绘必漂移）。

**归属与规模**：本条并入本卡（不新开卡）；工作量约 **+0.5 点**（lint 判据 + 反向对照 + 6 份现存文档补声明），完成时同步更新 §证据与 `verify/README.md`。
