## 1. 设计判定：为什么**不**合并成一份代码

**判定 = (b) 归一化是生产逻辑；判据不得导入它。**

| 选项 | 结论 | 依据 |
|---|---|---|
| (a) 提取规范件、两侧导入 | **不采纳** | 本仓 `verify/*.py` 是独立判据。判据导入被测实现 ⇒ 判据不再独立，这是**新增**缺陷；且为一个两行纯函数引入跨 `scripts/`↔`verify/` 的共享模块，把"写入侧与判据侧"耦合成同一份可被改写物。 |
| (b) 判据保留独立实现 ＋ 一致性向量 | **采纳** | `_norm_sprint` 的调用者是 **CLI 写入路径**（`register` 的 fail-closed 拒绝、`set-sprint` 的落库值），属生产逻辑；读取侧本来就必须**独立**再判一次。守它的正确机制是"两侧各自跑同一组输入、比对结论"，不是共用一份代码。 |
| (c) 三处语义不同 | **不采纳（但 E1 前提有误）** | 见第 2 节：独立的实现只有**两处**，且两处**逐行同义**，不存在第三种语义。 |

**反对 (a) 的关键点**：oracle 导入被测实现后，"两侧一致"是**同义反复**——
判据永远绿，正是台账 E1 反证列描述的"自检仍全绿"。故 (a) 是在制造
`docs/3-LEARNED.MD` 所说的"闸门全绿而判据已失效"。

## 3. 规范性口径（两侧必须同义，措辞不绑定实现）

`sprint-id` 的**规范值** = 不含前导零的十进制编号字符串（如 `18`）。

1. **必须接受**：`Sprint-18`、`Sprint 18`（空格分隔）、`sprint-18`（小写）、
   裸编号 `18`、带前导零 `018`、首尾空白。
2. **必须拒绝**（归不出编号）：`Sprint-`（只有前缀）、`abc`、
   非 Sprint 形态的标识（日期、run id）、**全大写 `SPRINT-18`**。
   > 全大写被拒是**现状事实**：两侧共用同一模式 `[Ss]print`，只容忍首字母大小写。
   > 本档**冻结**该事实为契约（改大小写口径必须同时改两侧与向量表）。
3. **两侧对"拒绝"的**处置**不同，且这是有意的**：
   - 写入侧（`scripts/agent-ops.py`）：拒绝即 fail-closed（`SPRINT-ID-ERROR`，不落库）；
   - 读取侧（`verify/verify_close_readiness.py`）：拒绝得 `None` ⇒
     该 run 身份不可派生 ⇒ 调用方**保留**它并计数上屏（宁多勿少，不猜）。
   **差异在拒绝之后，不在归一化本身。**

## 5. 反证（本档的判据"有牙"的证明）

向量若对"漂移"不敏感，它就只能恒绿。故两侧都断言：

> 把读取侧模式做一次**看似合理的收紧**（`0*(\d+)` → `0*(?:0*)(\d{0,4})`），
> 在同一组向量上重跑 ⇒ **至少一个输入的结论必须改变**。
> 若一个都没变 ⇒ 判 FAIL：**向量对该漂移不敏感 ⇒ 本次"一致"不作数**。

该收紧在真实向量上确会分叉：向量 A15 的输入左侧归 `18`、收紧后归 `0018`。
故前置条件可构造、可断言；断言写在脚本里，每次运行都真跑，不靠本档这句话。
