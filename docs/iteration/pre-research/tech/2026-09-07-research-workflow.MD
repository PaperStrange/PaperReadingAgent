# 预研笔记：调研工作流深化（research-workflow）

> 状态：**设计草案待确认，已开卡 M16**（2026-09-07）。本笔记是 M16 开工时 planning_pipeline 的强制上下文输入。
> 归属：`docs/iteration/pre-research/tech/`（仅 windows 分支维护）。

## 1. 背景与用户要求

用户（2026-09-07）：当前只有做需求时才用子代理做深入调研，且对话中只能看到调研结果、看不到调研过程；需要构建更快速更高效的调研 workflow。三个目标：
1. **按调研深度区分响应机制**——工程级 / 领域专家级 / 研究学者级，对应不同场景做更合适的响应；
2. **正式决策前的上下文、关键决策证据落档为安，严格遵循唯一真相**；
3. **调研内容可溯源、可直接用于下一步"引经据典"讨论**——溯源到数据源的**具体文字段落**，并在留档文档的**附件**中附上当时引用该内容生成调研结果的**思考过程**。

## 2. 设计草案（主代理方案，待用户确认）

### 目标 1：三级深度响应机制

| 级别 | 适用场景 | 响应机制 |
|---|---|---|
| **工程级（engineering / quick）** | 实现问题、工具用法、代码级选型、快速查证 | 3~5 源、单一维度、短时；**主代理直接执行或轻量子代理**（成本最低、响应最快） |
| **领域专家级（expert / normal）** | 方案选型、最佳实践、跨方案对比（现有 tech-research 默认档） | 子代理 tech-research：6~10 源、≥3 维度、对比矩阵、结论+取舍+翻案条件 |
| **研究学者级（scholar / deep）** | 架构决策、影响深远的技术路线、发布级判断 | 子代理 deep：≥12 源、全 tradeoff、反向证据、段落级引用全覆盖、可复现证据链 |

触发规则：任务/卡标注深度 → planning_pipeline 按关键词 + 决策影响自动建议级别 → **用户可覆盖**。

### 目标 2：决策证据落档（唯一真相）

调研 run 归档升级为固定目录结构（`agents/runs/<run_id>/`）：
- `report.md` —— 调研结论（现有格式）；
- `context.md` —— **本次调研的输入上下文快照**（question、注入的预研笔记、用户决策基线、深度级别）——"正式决策前的上下文"落档；
- `evidence/` —— **关键证据快照**：每个引用段落的原文 + 来源 URL + 抓取时间；
- `reasoning.md` —— **思考过程附件**：哪几段证据合起来推出哪个结论、为什么采信/排除某源。

### 目标 3：段落级溯源 + 思考过程

- 引用格式升级：每条事实 = URL + 来源层级 + **原文段落摘录（存 evidence/，报告内嵌引述）** + 该段如何支撑结论的一句话；
- 报告尾部附**证据索引表**（结论行 → evidence 文件名 + 段落摘录），支持"引经据典"式下一步讨论；
- `reasoning.md` 即目标 3 要求的"引用→结论思考过程"附件。

### 落地范围（M16 卡，~6 点）

1. tech-research spec v2.0（英文正文）：三级深度映射 + 段落级引用 + evidence/context/reasoning 归档结构；
2. fanout.json planning_pipeline research 步：depth 路由字段（场景→级别建议规则）；
3. 归档模板与校验（agent-ops 或新增脚本：归档结构完整性检查——可纳入 verify 覆盖矩阵）；
4. **首跑演示**：与 F-AC8（provider 模型官网调研）联跑——用「领域专家级」产出带段落级证据的调研报告，作为三级机制的样板；
5. 文档同步：agents/README、1-WORKFLOW §4.4。
