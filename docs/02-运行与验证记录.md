# PaperReading 运行手册与验证记录（macOS 版）

## 1. macOS 原始部署与运行方式

来自 `常用sh命令合集.txt` 的原始命令：

```bash
# 激活环境（venv 位于 paper-qa/.venv，Python 3.13，由 uv/venv 管理）
source "/Volumes/Extreme SSD/vscode_projects/PaperReading/paper-qa/.venv/bin/activate"

# 加载密钥（bash 风格 .env）
source ~/.secrets/paperqa.env

# 运行测试（仓库在 mac 上用 uv 管理）
uv run pytest -n auto

# 启动 ReactFlow 原型后端 (127.0.0.1:8787)
pip install -r ".../reactflow-paperqa-prototype/backend/requirements.txt"
python ".../reactflow-paperqa-prototype/backend/main.py"

# 启动前端 (127.0.0.1:5173)
cd ".../reactflow-paperqa-prototype/frontend"
npm install
npm run dev

# CLI 交互式问答（输出日志）
"$VENV/bin/python" ".../paper-qa-script/manual_index_paper.py" 2>&1 | tee tmp.log
```

macOS 环境关键版本：Python 3.13（Homebrew）、paperqa `2026.1.6.dev10+g36348d0ca`（本地源码）、
依赖锁定见 `paper-qa/uv.lock`（fhlmi==0.42.1、litellm==1.76.1、tantivy、aviary 等）。

## 2. 验证方式与记录

本仓库为 macOS 原始代码，无法在 Windows 上原生运行；按任务约定，采用**对原代码的模拟运行验证**：
把原文件完整复制到独立环境（逐字节一致），在 Windows x64 + Python 3.13 上安装其依赖并执行验证，
从而发现原文件自身的问题（该类问题在 macOS 上同样会发生）。

### 2.1 模拟验证环境

- 系统：Windows 11（x64），Python 3.13.2，Node v23.10.0 / npm 10.9.2
- 依赖安装：本地源码 `paper-qa` + `paper-qa-pypdf[media]` + `paper-qa-pymupdf`（uv.lock 版本：fhlmi 0.42.1、litellm 1.76.1）、streamlit、fastapi、uvicorn、pymupdf、graphviz(py)、sentence-transformers
- 原服务端点（DashScope）账户欠费后不可用，验证转向 DeepSeek 平台（见 Windows 仓库说明），
  但**原代码的导入/启动/结构验证均已完成**：paperqa 导入、FastAPI app 全部 8 条路由、RuntimeTracer、streamlit、litellm、PyMuPDF 页渲染（PaperQA2.pdf 25 页）、graphviz python 包、pymupdf 解析器自动发现。

### 2.2 发现的原文件代码缺陷（模拟运行中报错，已按授权直接修复）

**缺陷：`paper-qa-script/runtime_trace.py` 的 `RuntimeTracer._install()` 破坏 staticmethod/classmethod 语义。**

- 现象：后端 `load_index` 步骤（在 RuntimeTracer 上下文内执行 `get_directory_index`）报错
  `TypeError: SearchIndex.filehash() takes 1 positional argument but 2 were given`，
  最终以 `ExceptionGroup: unhandled errors in a TaskGroup (1 sub-exception)` 浮出。
- 根因：`_install_module_targets()` 会把类上的 `@staticmethod`（`SearchIndex.filehash`）也纳入补丁目标；
  `_install()` 通过 `getattr(cls, name)` 拿到未绑定的纯函数后直接 `setattr(cls, name, wrapped)`，
  导致静态方法被替换成普通实例方法——经实例调用 `self.filehash(body)` 时包装器收到 `(self, body)` 两个参数，
  而原函数只接受 `body` 一个参数。`@classmethod` 存在同类问题（多传 cls 会被当作第一个实参）。
- 影响范围：所有在 `RuntimeTracer` 上下文内执行且触发索引写入（`SearchIndex.add_document`）的流程
  （后端 load_index、Streamlit 构建索引）都会失败——**macOS 上同样会触发**。
- 修复：`_install()` 改用 `inspect.getattr_static()` 探测原始描述符；若是 `staticmethod`/`classmethod`，
  包装后仍以对应描述符形式安装，并在 `__exit__` 还原原始描述符。纯函数路径行为不变。
- 修复文件（本次唯一直接修改的原文件）：`paper-qa-script/runtime_trace.py`。

## 3. 与 Windows 版的差异提要

- macOS 版模型：`openai/qwen-omni-turbo`（LLM/摘要/增强）+ `openai/text-embedding-v4`（向量化），
  均走 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
- Windows 版改动（详见 Windows 仓库 `docs/`）：DeepSeek LLM + 本地 sentence-transformers 向量化、
  DeepSeek 视觉模型做图片增强与证据摘要、关闭思考模式（extra_body）、路径可移植、启动脚本（ps1）、
  `runtime_trace.py` 同一缺陷修复。
